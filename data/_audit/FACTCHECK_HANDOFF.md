# vernhaven(건강 블로그) 사실검증 — 진행 상황과 이어받는 법

작성: 2026-08-29 / 대상: **미발행분만**(발행된 글은 손대지 않음)

## 왜 하는가
건강 콘텐츠는 구글 품질 평가상 YMYL이라 가장 엄격한 잣대가 적용된다. 본문에
연구·기관·수치가 매우 구체적으로 인용돼 있는데 그게 맞는지 검증된 적이 없었다.
전수 대조 결과 오류는 전면적이지 않고 **특정 지점에 몰려 있다** — 잘 쓰인 글이
대다수인데 몇몇 자리에서 수치가 부풀려지거나 조건이 탈락한다.

## 찾아야 할 오류 8유형
`data/_audit/ko_known_issues.json`의 `_types`가 원본(다른 세션이 정의).
1. 출처를 못 찾는 수치
2. 존재를 확인 못 한 논문 인용
3. **실존 논문의 수치 부풀리기** — PREDIMED 30%→39%, 편두통 치즈 27.7%→70%
4. 실존 연구를 무관한 주제에 갖다 붙이기 — IARC 대장암 수치를 새치 근거로
5. 맥락 오용(수치는 맞지만 다른 실험 조건)
6. **전제 자체가 공식기관에 반박됨** — 대두 이소플라본 열감 감소(EU가 2012년 표시 금지)
7. 보도자료 수치를 논문 수치처럼 인용
8. 원문 오독

**3번과 6번이 제일 안 걸린다** — 수치가 그럴듯하다. 원논문 초록의 실제 값(HR/OR/%)을 직접 봐야 한다.

## 도구
- `python3 -m lib.content_review <topic> <lang>` → `check_unsourced_claims`가
  "수치는 있는데 그 문장·앞 문장에 출처 신호가 없는" 자리를 9개 언어 기준으로 뽑는다.
  **틀렸다는 뜻이 아니라 확인이 필요한 자리라는 뜻.**
- `python3 -m lib.claim_audit <topic>` → 다른 세션이 만든 ko 전용 감사기.
  `data/_audit/ko_known_issues.json`의 확정 오류가 재발하는지 본다.
  ⚠️ ko flat 경로만 읽으므로 언어 하위폴더는 커버 안 함.
- 조건 누락(유형 5)은 기계가 못 잡는다 → `MANUAL_REVIEW_CHECKLIST` 7-1·7-2를 직접 확인.

## 반영 방법 — 반드시 두 곳
1. DB: `blog_posts` `id=eq.<id>`로 `body_html` PATCH
2. 원본: `data/<topic>/<lang>/platform_captions.json`의 `blog_seo` 항목

⚠️ **원본은 이미지가 `PENDING:` 마커라 DB 본문과 전체 일치가 안 된다.** 전체 비교로
검사하지 말고 **텍스트 조각 단위로 치환**할 것(이걸로 한 번 헛돌았다).
⚠️ `<img>` 태그는 개수·src·alt 전부 무변경 — PATCH 전 어설션으로 확인.

## 이 환경의 함정
- **컴퓨터 절전으로 장시간 에이전트가 죽는다.** 이번에 7개가 그렇게 죽었다.
  → 긴 에이전트 대신 **한 글 고칠 때마다 즉시 반영**하고 넘어가는 방식으로.
- **중첩 위임 금지.** 최상위 에이전트가 자기 하위 Agent 완료 후 자동으로 안 깨어나
  그대로 정지한다. 피어 세션 18개와 슬롯도 공유한다.
- **네트워크 타임아웃이 잦다.** Supabase 요청에 재시도(3~4회, 백오프)를 넣을 것.
- **PubMed는 WebFetch가 쿠키 벽에 막힌다.** `europepmc.org`·저널 사이트·각국
  공식기관 페이지를 쓸 것. **막힌 페이지를 받았을 때 내용을 지어내지 말 것.**
